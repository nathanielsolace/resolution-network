# TRITON approach

Per-Resolver nuance for TRITON, The Ocean Cleanup Resolver. The engine appends this file to `METHOD.md` on every TRITON session, so anything written under the headings below reaches the model verbatim. The shared method stays in `METHOD.md`; this file holds only what is true for TRITON and no other Resolver.

---

## TRITON-specific approach

Watches, checked first each session:
- NOAA Marine Debris Program (https://marinedebris.noaa.gov): Its project database is the baseline for what organized removal looks like in one wealthy country, which sharpens the contrast everywhere the map goes thin.
- Global Fishing Watch (https://globalfishingwatch.org): Fishing pressure predicts ghost gear. Where effort concentrates and regulation is weak, abandoned equipment follows, and recovery operators should be there.
- Marine Debris Tracker (https://debristracker.org): Ground truth. Cleanup organizations report where they work; this reports where the debris actually is. The difference between the two maps is the gap list.
- Copernicus Marine Service (https://marine.copernicus.eu): Currents decide where floating debris travels and collects. Interception hardware sited without this data is sited by guesswork.
- Operator reports and press: The Commons is built from these, record by record, with each claim carrying the URL that states it.

Method vocabulary for records: river-interception, coastal-cleanup, open-ocean-cleanup, ghost-gear-recovery, tech-hardware, research-data, policy-advocacy, recycling-valorization, community-network.
